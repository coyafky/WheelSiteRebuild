# Next.js 与 Payload 内容架构

本文件记录 2026-10-31 用户确认的首期技术与内容管理边界。它是实施设计，不表示应用已安装、运行、验收或发布。公开页面及路由的权威规范仍见 [Sitemap](SITEMAP.md)。

## 应用边界

- 使用一个 Next.js 应用承载公开网站与 Payload 管理后台。Next.js 负责公开路由、页面模板和交互；Payload 负责首期产品平台与 Blog 的内容、媒体和发布状态。
- 公开页面结构由代码定义。管理人员编辑预设内容字段，不在后台任意改变页面结构。
- 首期由 Payload 管理四个固定产品平台页：轮毂、新能源三电壳体、铝制品定制和安全轮胎。不为具体型号建立独立详情页。四个平台的公开路径沿用 [Sitemap](SITEMAP.md)；内容记录以稳定的平台标识对应固定路径。
- 首页、三个固定轮毂子页、能力页、How We Work、About 与 Manufacturing 等其他页面的正文首期按固定页面实现。旋压、锻造、定制轮毂子页的主题内容、媒体和 SEO 分别审定，不新增产品平台或可任意创建的类别集合；首页入口复用对应平台与子页的已审定摘要，避免重复维护。具体路径和职责见 [Sitemap](SITEMAP.md)。
- 首期内容字段、媒体证据及固定页面数据契约的规划见 [Site Content Model Spec](../../.scratch/site-content-model/spec.md)。另有已确认的 [RFQ 功能设计草案](../../.scratch/rfq-system/RFQ-System-Spec.md)拟扩展 ProductModel、Inquiry 与附件记录；实施前须核对该扩展的字段级 schema、权限和发布门槛，本文件不表示扩展已安装。

## 内容模型

| 内容 | 已确认的结构与边界 |
| --- | --- |
| 产品平台 | 四条固定记录；共用标题、简介、图片、询盘入口和 SEO 信息等基础字段，并允许各平台使用专有内容区。字段与内容形状的规划见 [Site Content Model Spec](../../.scratch/site-content-model/spec.md)；实际 Payload schema 与校验仍待实施。 |
| 固定轮毂子页 | 三个代码定义的主题记录，分别承载旋压、锻造、定制轮毂的独立正文、经核实的媒体/证据引用和 SEO；复用 Wheels 平台的稳定 ID，不产生产品型号详情或额外 CMS 集合。 |
| Blog 文章 | 一个文章集合，以“技术说明”和“公司动态”区分类型；文章可关联相关产品平台或能力页。文章详情路径为 `/blog/{slug}`，分类列表路径沿用 [Sitemap](SITEMAP.md)。 |
| 媒体 | 由 Payload 管理产品和文章所用媒体；正式环境使用对象存储，具体服务商待部署阶段确定。 |

Payload 内容数据库选用 PostgreSQL。本地应用与 VPS/Docker 配置基线已建立，具体版本、文件和未完成的生产条件见 [Project Bootstrap](PROJECT_BOOTSTRAP.md)。对象存储服务商、生产凭据、备份及部署验收尚未确定。[Payload 数据库文档](https://payloadcms.com/docs/database/overview)与[存储适配器文档](https://payloadcms.com/docs/upload/storage-adapters)说明了相应适配能力。

## 编辑与公开发布

- 管理人员可以保存草稿、预览并自行发布，不设置独立审核角色或发布审批权限。对外主张、图片权利和文章内容仍须在公开前核实；这是一项内容责任，不由后台角色审批强制执行。
- 测试文章可以先在后台创建，以草稿和预览方式验证；测试内容不出现在公开站点。
- Blog 栏目由管理员统一开放，前提是至少有一篇已审定并发布的文章；不要求两个分类各有一篇。栏目开放前，Blog 导航和文章路由不对公众开放。栏目开放后，没有正式文章的分类不显示入口或公开列表页。页面规划状态和路由规则以 [Sitemap](SITEMAP.md) 为准。
- 文章 slug 在发布后保持稳定。确需修改时，为旧地址设置永久重定向；分类变更不改变文章详情地址。
