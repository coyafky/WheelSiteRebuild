Hero 组件怎么读

每个页面顶部那一块大标题，都走同一个组件：site/src/components/hero/hero.tsx。页面负责写人话，组件负责标题层级、字号、按钮、图片位置，以及「写错了就让构建失败」。

这份 HTML 是讲解。组件该怎么做，以 Global Hero Spec 为准。源码里的注释如果和校验代码不一致，以校验代码为准。

页面上它长什么样

窄屏时，文字在上、图在下。宽屏（1024px 起）时，左边文字，右边图，文字列稍宽。图可以不传。不传时，右边整列都不渲染，左边标题、说明和按钮照样完整。

Four platforms. Two ways to work.

一段属于这一页的短说明。一行大约 55 个字符，读起来不用横扫整屏。

Explore platforms Work paths →
Approved product imagery pending

红色胶囊只有一个，那是主操作。旁边的文字链接是次操作，带一个不读出来的箭头。占位盒子上的字是给内部看的，告诉你这还不是产品照片。

源码分成哪几块

整个文件大约 250 行，没有 'use client'。它是服务端组件。useId 在服务端也能用，只为了生成不重复的标题 id。

块名字它干什么
字号和边距displaySize pageSize standaloneFrame首页标题、普通页标题、独立使用时的页面边距。数字来自 Design.md，不在组件里再发明一档中间字号。
类型HeroProps HeroAction HeroMedia规定页面能传的形状。传错形状，TypeScript 先拦一层。
主函数Hero检查标题和说明，解析两个动作，拼出网格。页面自己已有外框时只返回网格。
图renderMedia renderApprovedImage只接受「已批准的图」或「写明待核实的占位」。别的形状直接抛错。
守卫isPendingMedia isMediaImage运行时再查一遍。图片必须有非空地址，以及正整数的宽和高。
动作resolveAction把「路由 id」或「页内锚点」变成真正的 href 和可见文字。

页面能传什么

调用方看到的就是 HeroProps。除了标题和说明，其余都可以不传。

属性必填含义
title是这一页唯一的 h1。写买方要办的事，或这一页的主题。
description是标题下面那段短说明。
pageType否，默认 pagehome 用更大的 display 字号。其他页用 h1 字号。
media否一张带尺寸的图，或一个待核实占位。没有第三种。
primaryAction否那颗红色胶囊。最多一颗。
secondaryAction否旁边的文字链接。最多一条。
embedded否true 时，组件不再包 <section>，也不再加自己的最大宽度和上下留白。外层页面已经有了。
headingId否给 h1 一个稳定 id，例如 home-hero。不传就用 useId() 生成，避免两个实例撞同一个 id。
className否追加到网格上。布局主规则仍在组件里。

规格是一页一个 Hero。 代码允许两个实例各自有 id，那是为了不制造重复 id。不要因为技术上能渲染两个，就在同一页放两个大标题。

函数从上到下怎么跑

1

标题或说明去掉空白后是空的，立刻 throw。页面不会带着空白大标题上线。

2

如果传了 headingId，它必须是小写字母开头的 slug，例如 home-hero。不能有空格、大写或 #。

3

决定标题 id，再按 pageType 选字号类名。首页是 40/44，到 1024px 变成 60/64。普通页是 34/40，到 1024px 变成 48/54。字重都是 650。

4

有主操作或次操作，就调用 resolveAction。没有，按钮那一行整个不渲染。

5

拼一个网格：左列最宽 720px，说明最宽约 55 个字符。有 media 才渲染右列。

6

embedded 为真，到这里就返回网格。否则再包一层 <section aria-labelledby="标题 id">，并加上 1500px 内容宽度和 Design.md 的上下留白（76 / 96 / 136 px）。

<h1 id={titleId} data-size-token={sizeToken}>{title}</h1>
<p>{description}</p>
{primary ? <Button asChild><a href={primary.path}>...</a></Button> : null}
{secondary ? <a href={secondary.path}>...</a> : null}
{media ? renderMedia(media) : null}

data-size-token 不参与样式。测试用它确认首页拿到的是 type.display，其他页是 type.h1。真正的字号在 displaySize 和 pageSize 两串 class 里。

文案归谁

组件内部没有一句对外宣传。首页那句 “Four platforms. Two ways to work.” 写在 site/src/components/home/home-view.tsx 的调用处，作为 title 传进来。

所以改文案时，去调用 Hero 的那个页面改。不要把某句话写进 hero.tsx。这个组件会被每一页复用，写死一句话，所有页都会带上它。

标题要能当这一页的名字。说明接着把这一页在说什么讲完。组件不检查句子好不好，它只拒绝空白。

按钮和链接

HeroAction 是两种对象里的一种，不能混成第三种写法。

页内锚点

primaryAction={{ label: 'Explore platforms', anchor: '#platforms' }}

anchor 必须长得像 #platforms 或 #work-paths：井号加上小写 slug。单独一个 #、大写、空格都会抛错。标签不能空。组件不会去 DOM 里查这个 id 在不在。注释里写了 “必须指向已经存在的 section”，那一句比代码多承诺了。调用的人要自己保证页面上有对应的 id。

站内路由

primaryAction={{ routeId: 'request-quote' }}
secondaryAction={{ label: 'See how we work', routeId: 'how-we-work' }}

routeId 不是网址。组件把它交给 requireNavigationRoute，从 site/src/navigation/route-registry.ts 取出路径。询盘因此会去 /request-quote，组件里没有第二份 URL 清单。

  • 路由还没发布，例如现在的 blog，直接抛错，页面上不会出现一条点进去是空的链接。
  • 不传 label 时，用登记里的标签。request-quote 的登记标签是 “Request a Quote”。
  • 传了标签但全是空格，抛错。空格在 JavaScript 里是真值，如果用 label || 登记标签 会渲染一颗没有字的红按钮。

主操作用共享的 Button，最低高度 44px，键盘焦点有描边。次操作是文字链接，同样最低 44px，箭头设了 aria-hidden，读屏只读文字。

图片和占位

还没有核准的图

media={{ pending: true, label: 'Approved product imagery pending' }}

这里不输出 <img>。输出一个 role="img" 的盒子，读屏名称会在你的标签后面加上 “not verified product imagery”。看得见的两个圆是装饰，aria-hidden。标签必须有可见文字，贴在实色底上，不叠到一张没核实的照片上。

已经批准的图

media={{
  url: '/media/wheel-stage.jpg',
  alt: 'A wheel on a neutral studio stage',
  width: 1600,
  height: 900,
}}

宽和高必须是正整数。组件用它们写 aspect-ratio，盒子在图片到达之前就占好比例。<img> 用 object-cover 铺满这个盒子，所以比例和原图不一致时会裁切。裁切不能切掉被当作证据的那一部分，选图时就要留出这个余地。

装饰图才把 decorative 设为 true，这时 alt 输出空字符串，读屏会跳过它。内容图不传 alt，或 alt 只有空格，会抛错。

不要把任意 JSX 塞进 media。 以前有过这个口子，调用方可以绕过 alt 和尺寸。现在类型只有上面两种。两种守卫都认不出的对象，renderMedia 抛错。

哪些输入会直接报错

这些 throw 是设计，不是漏网的异常。构建或渲染到这里就停，避免空白标题、死链接或一张说不清的图进页面。

输入结果
标题或说明是空的、或只有空格抛错
headingId 不是小写 slug抛错
占位没有可见标签抛错
内容图没有可用 alt抛错
图片地址是空的，或宽高不是正整数抛错
锚点不是 # 加小写 slug，或锚点没有标签抛错
路由未发布，或路由标签只有空格抛错
media 既不是占位也不是合格图片抛错

首页是怎么调用的

首页在 home-view.tsx 里自己有 <section> 和 1500px 的容器，所以 Hero 用 embedded。外层 section 的名字是 “Home hero”。Hero 内部的 h1 id 是调用方给的 home-hero。

<Hero
  pageType="home"
  embedded
  headingId="home-hero"
  title="Four platforms. Two ways to work."
  description="Explore Wheels, EV Housings, Custom Aluminum and Safety Tires. ..."
  primaryAction={{ label: 'Explore platforms', anchor: '#platforms' }}
  secondaryAction={{ label: 'Work paths', anchor: '#work-paths' }}
  media={{ pending: true, label: 'Approved product imagery pending' }}
/>

两个锚点对应同文件后面的 id="platforms" 和 id="work-paths"。首页 Hero 里没有指向 /request-quote 的按钮。这一页的询盘收在页面后部，不在首屏再重复一次。

新页面如果自己没有外框，就不要传 embedded。组件会自己输出 section、最大宽度和上下留白。记得仍只放一个 h1。

交给 AI 改之前先写进提示词

改 site/src/components/hero/hero.tsx 时保持这些约束：一页一个 h1；首页只用 type.display 两档字号，其他页只用 type.h1 两档，不要加 768px 的中间档；最多一个红色主按钮和一条文字次链接；网址只从路由登记来，不要在组件里写死路径；媒体只保留已批准图片和待核实占位，不要加回任意 React 节点；空白标题、空白说明、空白标签、未发布路由继续抛错；文字不要压在未核实的照片上。

改某一页的句子时，指出那个页面文件，不要改 Hero 的默认文案，因为它没有默认文案。改完跑：

cd site
pnpm exec vitest run --config ./vitest.config.mts tests/int/hero.int.spec.ts

这组测试锁着唯一标题、两档字号、一条主按钮、未发布路由、空 alt、占位标签和图片宽高。让 AI 改完却不跑这组测试，最容易把契约改松。
