# PageSpec — How We Work

Status: Launch（首发目标；规划完成不等于页面实现、内容验收或发布）。Route: `/how-we-work`。路由与页面职责以 [Sitemap](../../docs/02-架构/SITEMAP.md) 为准。

共享契约：[Page Shell](../global-page-shell/spec.md)、[Content Model](../site-content-model/spec.md)、[Interaction Spec](../site-interactions/spec.md)、[SEO Spec](../site-seo/spec.md)；本页使用 [hero](../global-hero/spec.md)、[breadcrumb](../global-breadcrumb/spec.md)、[inquiry-cta](../global-inquiry-cta/spec.md)。

## Audience and outcome｜访客与结果

准备开始标准采购或定制开发的买方；知道每阶段需提供和确认什么。

## Ordered content contract｜内容区块

1. 合作入口：标准采购与定制开发两条并列路径，说明适用情境。
2. 标准采购：询价、规格适配、样品、订单、出口交付的输入、双方确认点和下一步。
3. 定制开发：图纸/样件、工程评估、试制/测试、客户批准、批量生产的输入与确认点。
4. 常见前置问题：资料保密、目标市场和验证要求仅按已核实政策说明。

## Data and evidence｜数据与证据

固定代码页面；流程来源为原始产品资料和 Sitemap，具体周期、报价、NDA 范围与交付承诺须单独核实。

## Interaction and navigation｜交互与导航

两条路径各有清晰 CTA：标准采购预选 product；定制项目可预选 custom_project，OEM/ODM 由访客显式选择或通过明确入口预选。无经销授权申请流程。

## SEO contract｜搜索与分享

标题主题为合作流程；描述区分标准采购与项目定制。BreadcrumbList 可表达 Home → How We Work；不为阶段创建独立路由。 规范 URL、索引门槛、分享图与结构化数据校验遵守全站 SEO Spec；最终标题和描述须依据已审定内容填写。

## Acceptance｜验收条件

- 两条路径的阶段、客户输入和确认责任可逐项读懂。
- CTA 只预填来源明确的信息，访客可以修改。
- 无未经核实的交期、保密或授权承诺。
- 首发标记仅代表计划范围；必须有本次实现、内容核实和页面验收的直接证据才能标为已完成。
